Multi-Objective Metrics¶

When a surrogate is used to explore trade-offs between outputs (lower drag and higher lift, cheaper and stronger), per-output R² is not enough. What matters is which designs the model would pick as Pareto-optimal, and how good those designs really are. multioutreg.metrics scores that with three decision regrets. The model’s picks are the rows on the Pareto front of its predictions; each regret evaluates the true objectives at those picks against the true Pareto front. All three are 0 when the picks contain the true front, are never negative, are in the units of the objectives, and assume every objective is minimized (pass minimize=[...] to mix minimized and maximized columns).

Metric

Question it answers

Sensitive to

Hypervolume regret

How much of the trade-off space do the picks lose?

The whole front, on average

Scalarized regret

How much worse is the design the model prefers, for a given preference?

Typical preferences between objectives

ε-regret

What is the largest shortfall anywhere on the front?

The single worst-covered region

Each has a front_* counterpart that compares the predicted front with the true one instead: how well the predictions reproduce the front, rather than what acting on them costs.

A short example¶

Two objectives on a ZDT1-like front, and predictions with a little noise:

import numpy as np
from multioutreg.metrics import (
    epsilon_regret, front_epsilon_regret, front_hypervolume_regret,
    front_scalarized_regret, hypervolume, hypervolume_regret, scalarized_regret,
)

rng = np.random.default_rng(0)
f1 = rng.uniform(size=200)
Y_true = np.c_[f1, 1 - np.sqrt(f1) + 0.1 * rng.uniform(size=200)]
Y_pred = Y_true + rng.normal(0, 0.05, size=Y_true.shape)
ref = np.array([1.1, 1.2])                       # worse than every point
W = rng.dirichlet(np.ones(2), size=8)            # 8 preference weightings

hypervolume(Y_true, reference_point=ref)                  # 0.9565

# Decision regret: what acting on the model's picks costs
hypervolume_regret(Y_true, Y_pred, reference_point=ref)   # 0.0421
scalarized_regret(Y_true, Y_pred, weights=W)              # 0.0336
epsilon_regret(Y_true, Y_pred)                            # 0.0634

# Front fidelity: how closely the predicted front matches the true one
front_hypervolume_regret(Y_true, Y_pred, reference_point=ref)  # 0.0
front_scalarized_regret(Y_true, Y_pred, weights=W)             # 0.0546
front_epsilon_regret(Y_true, Y_pred)                           # 0.0044

The two views disagree, and the decision regret is the one to trust when the model will choose designs. Noise pushes some predicted points past the true front, so the predicted front covers at least as much volume as the true one and the clipped front_hypervolume_regret is 0. Acting on those predictions still loses hypervolume, because some of the rows the model calls Pareto-optimal are not. A model cannot lower decision regret by over-promising: shifting every prediction by a constant leaves its picks, and the regret, unchanged.

Definitions¶

Write \(y_k\) and \(\hat{y}_k\) for the true and predicted objectives of row \(k\) (same rows in both), \(T\) for the true Pareto front, and \(S = \{\, y_k : \hat{y}_k \text{ is on the Pareto front of the predictions} \,\}\) for the true values at the model’s picks. \(m\) is the number of objectives and \(r\) the hypervolume reference point.

Hypervolume is the volume dominated by a set of points and bounded by \(r\):

\[\mathrm{HV}(F; r) = \lambda\Big(\bigcup_{f \in F} [f_1, r_1] \times \dots \times [f_m, r_m]\Big)\]

where \(\lambda\) is the Lebesgue measure. It is computed exactly for any \(m\). When reference_point is not given it is set, per objective, to the worst true value plus 10% of the range (front_hypervolume_regret uses both arrays); fix it yourself when comparing several models.

\[R_{\mathrm{HV}} = \mathrm{HV}(T; r) - \mathrm{HV}(S; r)\]

Scalarized regret asks, for each weight vector \(w \in W\) (rows clipped to non-negative and normalized to sum to 1), how much worse the row the model prefers is than the true best:

\[r(w) = w^\top y_{\hat{k}(w)} - \min_k w^\top y_k, \qquad \hat{k}(w) = \arg\min_k w^\top \hat{y}_k, \qquad R_{\mathrm{scal}} = \frac{1}{|W|} \sum_{w \in W} r(w)\]

reduce picks the summary ("mean", "median", "max", "dict" for several, "none" for every \(r(w)\)).

Additive ε-indicator regret is the smallest amount every objective of the picks would have to improve for them to weakly dominate the true front:

\[R_{\varepsilon} = \max_{t \in T}\ \min_{s \in S}\ \max_{i = 1..m}\ (s_i - t_i)\]

\(R_{\mathrm{HV}}\) averages over the whole front; \(R_{\varepsilon}\) is a worst case, so one badly missed corner sets it even when the rest is perfect.

Front versions. front_hypervolume_regret and front_epsilon_regret use the predicted front \(P\) in place of \(S\) and clip at 0; front_scalarized_regret uses \(r(w) = \min_k w^\top y_k - \min_k w^\top \hat{y}_k\), which is negative for pessimistic predictions and positive for optimistic ones. They accept arrays with different numbers of rows.

Ties. Identical predicted rows are mutually non-dominated, so a model that predicts the same vector everywhere picks every row and scores 0 hypervolume and ε regret. Check pareto_mask(Y_pred).sum() alongside the regret when predictions can tie.

In the app and the report¶

The Auto-Detect page computes the three decision regrets on the test split, lets you set a maximum for each, and the report shows them with PASS / FAIL in section 2 (“Multi-Objective Regret”). A failed bound also appears as a finding and a next step on the report’s front page; see Reading the Report.

Practical notes and defaults¶

  • When to tune the HV reference:
    If your objectives have known “worst acceptable” bounds or a natural operating region, set a custom reference point to improve interpretability and stability of HV.

  • When to customize weights:
    If stakeholders can articulate preferences, supply those weight vectors (each row sums to 1). Otherwise, use the defaults to summarize global performance across preferences.

  • How to interpret bounds (thresholds):
    If you set max acceptable values for HV, scalarized, or ε-regret, the UI will flag results:

    • ✅ when metric ≤ bound

    • ❌ otherwise

Computational notes¶

  • pareto_mask cost: dominance is checked between every pair of rows using (n, n, m) boolean arrays, so time and memory grow with n² · m. A few thousand rows is fine; for two objectives, n = 20,000 needs on the order of 2 GB. Filter or subsample very large candidate sets first.

API recap¶

from multioutreg.metrics import (
    pareto_mask,
    hypervolume,
    hypervolume_regret,
    scalarized_regret,
    epsilon_regret,
    front_hypervolume_regret,
    RegretTracker,
)

# Exact hypervolume of a front, any number of objectives
hv = hypervolume(Y_true, reference_point=ref, minimize=True)

# Decision hypervolume regret: true values at the designs the model calls Pareto-optimal.
# Y_true and Y_pred are the same candidates, row for row.
r_hv = hypervolume_regret(Y_true, Y_pred, reference_point=None, minimize=True)

# Front fidelity: predicted front versus true front (clipped at 0)
r_front = front_hypervolume_regret(Y_true, Y_pred, reference_point=ref)

# Scalarized decision regret across weights (1D/2D/scalar accepted; rows auto-normalized)
r_sc = scalarized_regret(Y_true, Y_pred, weights=[[0.5,0.5],[0.2,0.8]], reduce="mean")

# Additive epsilon indicator of the picks
r_eps = epsilon_regret(Y_true, Y_pred, minimize=True)

# Iterative tracking (records the three decision regrets)
tracker = RegretTracker(minimize=True, n_weight_samples=16)
stats = tracker.step(Y_true_batch, Y_pred_batch)

Shapes: Y_* are (n, m) or (n,) (treated as (n,1)); the decision functions need Y_true and Y_pred of the same shape.
Weights can be (k, m), (m,), (k,) (if m==1), or scalar (if m==1).

Joint predictive scores¶

The regrets above score where a model’s predictions land. energy_score and variogram_score score its joint predictive distribution: whether the uncertainty it reports for several outputs together, including how they co-vary, matches what happens. Per-output metrics cannot see this. Both are proper scores (lower is better) computed from samples of shape (n_rows, n_samples, n_outputs).

from multioutreg.metrics import energy_score, variogram_score, gaussian_samples

mean, cov = model.predict(X_test, return_cov=True)   # or return_std=True for independent outputs
S = gaussian_samples(mean, cov, n_samples=500, seed=0)
es = energy_score(Y_test, S)          # multivariate CRPS (Gneiting & Raftery 2007)
vs = variogram_score(Y_test, S, p=0.5)  # sensitive to wrong correlation (Scheuerer & Hamill 2015)

  • Energy score reduces to the CRPS for one output. It is dominated by errors in the means, so it separates correct from wrong dependence only weakly.

  • Variogram score compares pairwise output differences, so it reacts strongly to a wrong correlation and ignores a shift shared by all outputs. Report it with a marginal score.

  • Both use distances across outputs, so standardize outputs on very different scales first.

  • energy_score builds an (n, S, S, m) array; keep n_samples to a few hundred for large n.

Surrogates that return a covariance: GaussianCopulaSurrogate, PCAOutputSurrogate and MultiTaskGPSurrogate. The dtlz2 benchmark (multioutreg.active.benchmarks, front from dtlz_front) has strongly dependent outputs for testing them.

Defaults summary¶

  • HV reference: data-dependent worst + 10% span (per objective) if not provided, from Y_true for decision regret and from both arrays for front_hypervolume_regret.

  • Scalarized weights: required by scalarized_regret; RegretTracker samples 16 Dirichlet(1) vectors and the GUI’s Auto mode samples 8; 1.0 when m==1.

  • ε-indicator: parameter-free, but in objective units; standardize objectives to compare across them.

  • Minimization: by default, all objectives are minimized (pass minimize=[...] to mix min/max).

These defaults are chosen to be safe, scale-aware, and preference-agnostic, giving meaningful numbers without extra configuration, while still letting you override them when domain knowledge is available.
