Statistical / Logic Audit Checklist¶

Audit date: 2026-10-21. Items tagged [verified] were reproduced empirically (numpy<2, scikit-learn, uncertainty-toolbox 0.1.x); the rest come from code review.

Critical (results are wrong)¶

  • [x] 1. Conformal coverage calibrated and scored on the same test set. mor_cli/grid_search_auto_detect.py, multioutreg/gui/pages/01_Use_Auto_Detect_MultiOutput_Regressor.py called calibrate_conformal(X_test, y_test) and then measured coverage on X_test, so the reported coverage was in-sample and trivially ~1-alpha. Fix: hold out a calibration split from the training data.

  • [x] 2. Most surrogates report std = 0 (including GP). [verified] BaseSurrogate.predict called MultiOutputRegressor.predict(X, return_std=True), which raises TypeError; the fallback was np.zeros_like. GP/SVR/KNN/LR/DT/GB all claimed zero uncertainty. Fix: iterate estimators_ so models with native uncertainty (GP, BayesianRidge, …) report it.

    • [ ] Follow-up: models with no native uncertainty still return std = 0 (here, in AutoDetectMultiOutputRegressor.predict, MoE hard routing, BNN with n_mc_samples=1). NaN would be more honest, but the GUI/report feed best_std straight into uncertainty-toolbox plots, so those need NaN handling first.

  • [x] 3. Bootstrap LR resamples X and y with different indices. [verified] multioutreg/model_selection/screening.py (_blr) – fitted slopes ~0 on y = 3x.

  • [x] 4. get_uq_performance_metrics passes args in the wrong order. [verified] multioutreg/performance/metrics.py called uct.get_all_metrics(y_true, y_pred, y_std); the signature is (y_pred, y_std, y_true). Unit test mocked uct so never caught it.

  • [x] 5. Joint multi-output candidates (MoE) scored on training data vs CV for everything else. multioutreg/model_selection/auto_detect.py compared in-sample MSE to GridSearchCV.best_score_. Fix: score with out-of-fold predictions on the same CV splitter.

  • [x] 6. Time-series ranking compares different scales, all in-sample. ARIMA/SARIMA metrics are on the differenced series (in-sample one-step); LSTM on original scale (in-sample); Ranker averages ranks across these. Fix: hold out last H points, forecast every model on the original scale, then rank (optionally Diebold–Mariano). Decided: sample-size-dependent rolling-origin evaluation (all origins for small n, 10 for large n). Full writeup: Appendix A. Done (2026-10-28): ts_dynamic_fit/src/forecasters.py gives ARIMA, SARIMA, LSTM and a naive baseline one fit(y) / forecast(H) interface on the original scale; src/evaluate.py plans the origins (A.4), scores every model against the same values with one metric function, ranks on mean MASE and reports an HLN-corrected Diebold–Mariano test. ts-pipeline and the UI tab both call rank_forecasters. Reproduction (A.6 step 0, random walk with drift around 1000): before, ARIMA “won” with in-sample RMSE 4.8 on differences vs LSTM 11.5 on levels; after, all models are within MASE 1.37–1.47 of each other on the same targets and DM p = 0.52. See A.7 for deviations.

High (wrong statistics / assumptions)¶

  • [x] 1b. Multi-fidelity page had the same conformal bug as item 1. gui/pages/02_Multi_Fidelity_Surrogate_Models.py calibrated on test-set residuals and scored coverage on the same test set. Now calibrates on a held-out part of the hi-fi training split.

  • [x] 1c. Multi-fidelity page selected the best model by test-set MSE, then reported metrics on that same test set (optimistic). Now _select_best_candidate scores candidates by cross-validation over the hi-fi training rows, with the CV scheme chosen from their count (select_cv_strategy); the winner is refit on all training data and evaluated once on the test set.

    • Also fixed: “MultiFidelity+…” candidates were scored with their lowest-fidelity model, because MultiFidelitySurrogate.predict defaults to fidelity_levels[0] and the page passed no level (same for conformal calibration). The page now calls _predict_highest.

    • [x] Follow-up: the library default (level=None → lowest) is a trap for other callers; consider defaulting to the highest level or making level required. Done: level=None now uses the highest level (fidelity_levels[-1]).

  • [x] 7. “Std” is actually an interval half-width. screening.py _GBQ [verified: 1.53 vs true 1.0], gui/Grid_Search_Surrogate_Models.py (GradientBoostingWithUncertainty), ConformalPredictionNetworkSurrogate (90% |residual| quantile). Divide by 2*norm.ppf(1-alpha/2). Done: all three now divide by the matching z (and clip at 0 for crossed quantiles).

  • [x] 8. Conformal quantile clamps to max residual when n_cal is too small. [verified] conformal/base.py – when ceil((n+1)(1-alpha)) > n the interval should be infinite (or warn). Consider method="higher" for the exact order statistic. Done: returns inf with a warning when k > n; uses the exact k-th order statistic. The two copies in figures/conformal_plots.py now use the shared function, and the ordered-interval plot labels unbounded intervals.

  • [x] 9. CVPlusConformalPredictor is not CV+. Uses mean(fold preds) ± quantile(OOF residuals). True CV+ (Barber et al.) uses per-point quantiles of {mu_{-k(i)}(x) ± R_i}; guarantee is 1-2alpha. Implement properly or rename and drop the guarantee claim. Done: real CV+ (per-point order statistics); docstring states the 1-2alpha guarantee.

  • [x] 10. Normality tested on raw y, not residuals. [verified] screening.py test_normality. Done: test_normality(X, y) now tests OLS residuals (uniform X with y = 5x: raw y p < 1e-4, residuals pass).

  • [x] 11. No multiple-testing correction in screening. 3 tests × n_outputs at alpha=0.05, OR’ed together. Use Holm / Benjamini–Hochberg. Done: ModelScreener(correction="holm" | "bh" | None) adjusts the normality / RESET / BP p-values of all outputs jointly (default Holm), stores p_adjusted and flips FAIL→PASS when only the raw p was significant. Pure noise, 5 outputs, 40 runs: any-flag rate 20/40 → 3/40.

  • [x] 12. Breusch-Pagan confounded by mean misspecification. Run after a flexible fit or only when RESET passes. Done: BP only runs when RESET passes; otherwise it is reported as “not tested” (FAIL, p=None, excluded from the correction) so heteroscedastic models are kept rather than ruled out. Flexible fits were tried first and rejected: on constant-noise data with OOF residuals from RF, HistGB, splines or nearest-neighbour differences, BP falsely rejected 15–95% of the time whenever d > 1, because residual bias also varies with x.

  • [x] 13. Screening inconsistencies. VIF never used; screen() ignores nonlinear_dep; rule keys mismatch model names (sgp vs sgpr; et, nystroem_gp, elastic_net, lasso, quantile, ngboost, catboost default to True); pre_screen=True silently ignored unless built via with_vendored_surrogates(). Done: VIF failure adds BayesianRidge to screen() and notes it on LinearRegression; screen() includes the RF–LR gain test. Rules now use canonical keys plus aliases (gpr, ngb, GUI sgp = Nystroem, the screen() long names), covering every CLI/GUI name: et/catboost gated on non-linearity, ngboost on non-linearity or heteroscedasticity, quantile on non-normal residuals, scalable GPs (nystroem_gp, sgpr) and regularised linear models always eligible. Unknown names warn. pre_screen on a custom estimator list maps class names to rules, and falls back to all candidates if screening rules out every one.

  • [x] 14. MoE “EM” never looks at expert fit. Labels are reassigned from the gating net’s own predict_proba. Reassign by per-sample expert residual/likelihood. Soft-routing std omits within-expert variance (law of total variance). Done: E-step assigns argmax_k log π_k(x) + log N(y | μ_k(x), σ²) (σ² per output, pooled). Two linear experts on y = 3|x| now find the kink in 8/8 seeds (was 1/5). Also fixed: random-label init made the experts near-identical, so one took every sample; now k-means on standardised (X, Y), and an emptied expert is re-seeded with the worst-fit samples instead of refit on everything. Soft std = sqrt(Σ w_k (σ_k² + (μ_k − μ)²)); hard routing returns the chosen expert’s std instead of 0.

  • [x] 15. Unscaled features & weak GP defaults in model selection. Wrap SVR/KNN/MLP/GP/Lasso in Pipeline(StandardScaler(), ...). Default GaussianProcessRegressor() (alpha=1e-10, no WhiteKernel, no normalize_y) collapsed to RBF(1e-5) on noisy data [verified]. ARD GP lacks amplitude term. Done: BaseSurrogate(scale_inputs=...); GP, SVR, KNN, CPN (MLP), Lasso and ElasticNet surrogates default to scale_inputs=True, and AutoDetect grid-searches the same models as scaler pipelines (grid keys are un-prefixed before building the surrogate). GP defaults to C·RBF + White with normalize_y=True (gp_sklearn.default_gp_kernel); AutoDetect searches RBF vs Matern-5/2. On the verified case: test MSE 6.2 → 0.03. ARD GP is now C·ARD-RBF + White on standardised inputs with normalize_y. Screening factories use the same.

    • [ ] Follow-up: RFF / Nystroem GP grids (length_scale, gamma) are still in raw input units.

  • [x] 16. Model-selection statistics. GridSearchCV(cv=int) is unshuffled KFold; winner’s best_score_ is optimistically biased (no nested CV); no test of meaningful difference (1-SE rule / Nadeau–Bengio). mlp scored as MLPRegressor on 100% but deployed as ConformalPredictionNetworkSurrogate on 80%. Done: int cv → KFold(shuffle=True, random_state=0), one split list shared by every candidate (incl. joint MoE/BNN). selection_scores_ records each candidate’s mean CV score and Nadeau–Bengio corrected SE per output. selection="one_se" picks the least complex candidate within 1 SE of the best (default stays "best"). mlp is grid-searched as _CPNEstimator, i.e. the deployed CPN with the same random_state. Not done: nested CV — the docstring says the winner’s CV score is optimistic; the CLI and GUI already report metrics on a held-out test set.

  • [x] 17. Imputation leaks targets. grid_search_auto_detect.py KNN-imputes inputs and outputs on the full frame before the split. Split first; impute X on train only; drop rows with missing y. Done: new drop_unusable_rows (before the split: rows missing a target or a “drop” column) and impute_train_test (after the split: KNN fitted on training inputs only, using all input columns) in utils/imputation.py. Used by both CLI commands, the main app, page 01 and page 02 (per fidelity level, which previously also mixed levels). apply_imputation is no longer called.

  • [x] 18. PCA Kaiser rule on unscaled data. Four copies of the PCA block (mor_cli/grid_search.py, mor_cli/grid_search_auto_detect.py, gui/Grid_Search_Surrogate_Models.py, GUI page 01) ran PCA on raw inputs, so “eigenvalue > 1” depended on the inputs’ units. All four now call multioutreg/utils/pca_utils.py::fit_input_pca, which fits StandardScaler + PCA on train only and clips k to [1, n_features] (a manual k or a threshold of 1.0 could exceed it before).

Medium¶

  • [x] 19. KS sampling-method detector (mor_cli/use_ks_for_sample_bias.py): sums per-dim D, no p-values, single unseeded draw, marginal KS can’t separate LHS vs random, grid uses cbrt(n) for any d, beta grid ignores loc. Use qmc.discrepancy / NN-distance stats vs a simulated null. Done: new shared detector multioutreg/sampling/detect.py::detect_sampling_method. It computes stratum occupancy, centered L2 discrepancy (qmc.discrepancy, n ≤ 1000) and mean NN distance, and compares them with the same statistics on designs simulated by Random / LHS / Sobol (Sobol + Halton) of the same n and d. The statistics are combined into one Mahalanobis distance and a Monte Carlo p-value per method; the method with the highest p wins, or “Uncertain” if all p < 0.05. n_sim is 199 / 99 / 49 depending on n, so the smallest attainable p is always < 0.05. Grids are recognised by structure (few levels per input; full factorial, including when extra columns are derived features), and unscrambled Sobol / Halton by exact match. compare_sample_methods now maps inputs through their YAML CDFs (probability integral transform) and runs the detector on known bounds, so any marginal works. It reports a per-input KS test with p-values as a check of the YAML marginals only, and has --seed. Generators take an rng; grid levels are floor(m^(1/d)) at equal-probability stratum centres; beta uses loc; and YAML "None" strings are read as missing. Validation (10 seeded designs per cell, n ∈ {20, 100, 300}, d ∈ {2, 5, 10}): see item 20.

  • [x] 20. UMAP sampling classifier: ad-hoc absolute thresholds on UMAP distances; generate_umap_plot(None) fabricates random data. Label as heuristic; validate. Done: the thresholds are gone. generate_umap_plot (figures + the duplicate in report_plotting_utils), infer_sampling_and_plot_umap and the detect_sampling CLI take the method from detect_sampling_method. UMAP is now only the picture: it does not preserve distances, so its embedding cannot separate designs. None / empty input raises ValueError; fewer than 4 points gives “Uncertain” in the plot caption, and fewer than 10 points skips the MC test (“Uncertain”). The KMeans coloring was dropped. Validation (inputs rescaled to an arbitrary box, default n_sim, 10 seeds per cell, n ∈ {20, 100, 300} × d ∈ {2, 5, 10}, 90 designs per row): Random 85/90, LHS 81/90, scrambled Sobol 86/90, Halton → “Sobol” 77/90, normal inputs → “Uncertain” 71/90. At n ≥ 100 every cell is ≥ 8/10, and most misses are “Uncertain” (about alpha = 5%). At n = 20, normal inputs are often called “Random” (power is low) and Halton in d = 10 is 4/10. The old UMAP rules had no validation; on the repo’s example datasets they called the LHS file “not LHS” (E9).

    • [ ] Follow-up: designs with non-uniform marginals (e.g. LHS of normals) are “Uncertain” unless the marginals are supplied (compare_sample_methods), and the reports test X_train after the split / imputation / PCA, which hides a true LHS. Plan: Appendix B.

  • [x] 21. ts_suitability.py: Ljung-Box on levels (trend ⇒ “suitable”); “seasonal period” = first lag with |ACF|>0.3 (returns 2 for any persistent series); add KPSS alongside ADF. Done: KPSS (level) runs alongside ADF; the series is stationary only when ADF rejects and KPSS does not. Otherwise Ljung-Box runs on the first differences (new key tested_on), so a random walk is no longer “suitable” (its increments are white noise). The season comes from the new shared multioutreg/time_series/seasonality.py::detect_seasonal_period: the highest local ACF peak at lag ≥ 2 above max(0.3, 1.96/√n), with a dip before it, preferring the smallest such peak within 80% of the best (not a multiple of the period). Non-stationary series are scanned on the linearly detrended levels, then on the differences. Validation (50 seeds, n = 200–240): white noise, trends, random walks with and without drift → no period (random walk 48/50); AR(0.9) 47/50 none (was always 2); s = 7 → 50/50; trend + s = 12 → 50/50; random walk + s = 7 → 50/50. New keys kpss_statistic, kpss_pvalue; the existing keys are unchanged.

  • [x] 22. SARIMA detect_seasonal_period includes lag 1 ⇒ s=1 for almost any series. Done: delegates to the shared detector above (returns 0 when there is no season, as before). When s < 2 the grid only tries P = Q = 0: seasonal terms with s < 2 always failed in statsmodels, so 12 of the 16 fits were wasted.

  • [x] 23. ARIMA/SARIMA “MAPE” is |mean signed % error| — use mean(abs(...)). Done in the legacy run() (still in-sample, on the differenced series; the ranking no longer uses it and reports sMAPE on the original scale).

  • [x] 24. ARIMA differencing loop has no max d; forecasts/intervals on differenced scale. Fit ARIMA(p,d,q) directly. Done: the new forecasters choose d <= 2 with the ADF test and fit ARIMA(p,d,q) / SARIMAX on the undifferenced series; the legacy run() loops are capped at d = 2 too.

  • [ ] 25. ForecastAutoIntervals: quantile branch changes quantile without refitting (lower = mean = upper); bootstrap branch uses in-sample residuals and ignores horizon growth.

  • [x] 26. time_series/metrics.py: mase denominator should use the training series; weighted_quantile_loss is mean pinball, not Chronos WQL (2·Σpinball/Σ|y|). Done: mase(y_true, y_pred, y_train, seasonality=1) scales by the in-sample seasonal-naive MAE of y_train (finite for a 1-step window; raises if y_train has ≤ m points). weighted_quantile_loss now returns the mean over levels of 2·Σpinball/Σ|y|.

  • [x] 27. Epistemic-only uncertainty (RF/ET spread, MSE deep ensemble, MC-dropout): no aleatoric term ⇒ under-coverage. _EHet is not heteroscedastic. Document, add NLL heads, or conformalize. Done: DeepEnsembleSurrogate and BNNSurrogate take loss="nll" (new default): each network has a mean and a softplus variance head trained on the Gaussian NLL, and the std is that of the equal-weight mixture, sqrt(mean noise var + var of the member / MC-pass means) (Lakshminarayanan 2017; Kendall & Gal 2017). loss="mse" keeps the old epistemic-only spread, documented as under-covering. RF / ET (RandomForestSurrogate, ExtraTreesRegressorSurrogate, the grid-search *WithUncertainty wrappers and the RF interval plots in figures/confidence_intervals.py) now share surrogates/forest_uncertainty.py: std = sqrt(tree var(x) + c), where c = max(held-out MSE − mean held-out tree var, 0) per output, held-out = out-of-bag trees (RF) or 5-fold refits (ET, bootstrap=False). This makes the mean predicted variance match the held-out MSE; c is constant in x and smaller than the noise variance, because fully grown trees already fit some of the noise. include_noise=False returns the spread alone. _EHet keeps its bootstrap-RF spread and adds an RF noise model fitted on out-of-bag r² − v, so its std follows the noise. Validation (n_train = 400, d = 3, test n = 3000, two outputs: noise 0.1–0.6 and 0.3, two seeds), coverage of 90% Gaussian intervals before → after: deep ensemble 0.14–0.22 → 0.80–0.87, MC-dropout 0.34–0.43 → 0.92–0.95, _EHet 0.40–0.47 → 0.88–0.93, RF 0.80–0.86 → 0.86–0.92, ET 0.80–0.86 → 0.85–0.92. Correlation of predicted std with the true noise std: 0.97 (deep ensemble), 0.94 (MC-dropout), 0.95 (_EHet). What this means in practice:

  • Scale. If the series is differenced, ARIMA/SARIMA errors are on changes from one step to the next, not on levels. For a trending series the differences are much smaller than the levels, so ARIMA/SARIMA “win” on RMSE/MAE because they are measured on a smaller number, not because they forecast better.

  • MAPE is computed differently. ARIMA/SARIMA compute abs(mean(signed % error)), so positive and negative errors cancel out. That is not MAPE. On a differenced series the denominators are near zero, so the value blows up. LSTM computes mean(abs(% error)) and skips points where |y| < 1. The Ranker treats these as the same metric.

  • No holdout. Every model is scored on the data it was fitted on. Models with more parameters are favoured. The LSTM (about 200k parameters, 200 epochs) can memorise the series. The ARIMA grid picks (p, q) by AIC over 64 fits, which is fine for choosing an order but does not tell you how well it forecasts.

  • Horizon mismatch. ARIMA/SARIMA are scored one step ahead and LSTM ten steps ahead, which is a harder task.

  • Leakage in LSTM. The MinMaxScaler is fitted on the full series (algs/lstm.py:196).

Symptom already observed: E10. The CLI picked SARIMA and the UI picked LSTM on the same data. Part of that is the unseeded LSTM, and part is that the ranking is decided by small artefacts.

A.4 The decision: sample-size-dependent rolling-origin evaluation¶

Decided (2026-10-28): score models by rolling-origin evaluation. The number of origins depends on n: with few samples every possible origin is used (the time-series analogue of LOO-CV), and with many samples a fixed number of blocks is used (the analogue of k-fold). Each threshold below is either taken from the literature or marked as a convention.

Why not ordinary LOO / shuffled k-fold. Standard K-fold CV is valid only for purely autoregressive models with uncorrelated errors [Bergmeir, Hyndman & Koo 2018]. ARIMA with MA terms or differencing, SARIMA, and an LSTM fitted on overlapping windows do not meet that condition. For non-stationary series, out-of-sample methods that keep the time order give the most accurate estimates [Cerqueira, Torgo & Mozetič 2020]. Several forecast origins are better than a single fixed origin [Tashman 2000].

The rule (n = series length, s = detected seasonal period, 0 if none):

  1. Forecast horizon H. Use --horizon when given. Otherwise H = s if s ≥ 2, else H = 1. (Convention: a full season, so SARIMA is judged over one cycle. With no season, H = 1 is the one-step-ahead LOO analogue.)

  2. Test region T = the last max(H, ceil(0.2·n)) points. “The size of the test set is typically about 20% of the total sample … [and] should ideally be at least as large as the maximum forecast horizon required” [Hyndman & Athanasopoulos, FPP3 §5.8].

  3. Minimum training length = max(2·s, train_window + H, n_params + 1), i.e. at least two full seasonal cycles (statsmodels seasonal_decompose / STL refuse fewer) and more observations than parameters [Hyndman & Kostenko 2007, who also argue against fixed rules such as “at least 50 points”]. If n − T is below this minimum, shrink T toward H. If n − H is still below it, fail with a clear “series too short” error.

  4. Origins. Rolling origin with step 1 over the test region gives m = T − H + 1 possible origins [FPP3 §5.10, stretch_tsibble(.step = 1)]. Each origin refits on everything before it (expanding window) and forecasts H steps.

    • m ≤ 10: use all m origins (LOO analogue).

    • m > 10: use k = 10 evenly spaced origins (k-fold analogue). (The cap of 10 comes from the i.i.d. literature, where 5- or 10-fold is the standard recommendation [Kohavi 1995; Hastie, Tibshirani & Friedman 2009, §7.10]. No time-series paper gives a specific n cutoff. --folds k overrides it, e.g. --folds 5 to halve LSTM cost.)

  5. Score and rank with MASE [Hyndman & Koehler 2006], each origin scaled by the in-sample seasonal-naive error of its own training window, then averaged over origins.

  6. Significance: a Diebold–Mariano test [Diebold & Mariano 1995] with the Harvey–Leybourne–Newbold small-sample correction [Harvey, Leybourne & Newbold 1997] on the pooled forecast errors of the best and second-best model. This is reported only and does not decide the winner.

Cost control (not from the literature): ARIMA/SARIMA select the order once per origin block and use results.append(new_obs, refit=False) between origins inside a block. The LSTM refits at each origin used, so a long series costs at most k = 10 fits.

A.5 How to implement it¶

  1. Build the origins once, in the caller (mor_cli/ts_pipeline.py, and the UI page at the same point), by extending the existing WalkForwardCV / walk_forward_splits in multioutreg/time_series/cv.py rather than writing a new helper. It already does expanding (or max_train rolling) windows with min_train, horizon and step, and GUI tab 3 uses it. Add a constructor such as WalkForwardCV.from_sample_size(n, horizon, seasonality, min_train, max_folds=10) that applies the A.4 rule: test region, all origins when m ≤ 10, otherwise 10 evenly spaced origins. Even spacing needs either an explicit list of origins or a computed step. Every model then sees the same origins.

  2. Give every model the same interface: fit(y_train) and then forecast(H) -> np.ndarray on the original scale. Keep run() as a thin wrapper for backwards compatibility.

    • ARIMA / SARIMA: keep the ADF test to choose d, but fit sm.tsa.ARIMA(y_train, order=(p, d, q)) / SARIMAX(..., order=(p, d, q), seasonal_order=(P, D, Q, s)) on the undifferenced series, and pick (p, q) by AIC as today. With d passed to statsmodels, results.forecast(H) is already on the original scale. The manual un-differencing in src/infer.py:71-85 is then no longer needed, and the SARIMA diff_count bug goes away.

    • LSTM: fit the scaler on y_train only. Set output_size = H (forecasting all H steps at once), feed the last train_window training points, and inverse-transform. Seed torch and numpy (this also fixes E10).

  3. Score all models with one function in multioutreg/time_series/metrics.py, applied to (y_test, y_hat): RMSE, MAE, MASE (scaled by y_train; fix item 26 first), and sMAPE instead of MAPE. Delete the per-model metric code in algs/*.py so the three models cannot drift apart again.

  4. Ranking. In src/ranker.py, rank on origin-averaged MASE (A.4 step 5), because it does not depend on scale. Optionally keep the average rank as a tie-break. Report the HLN-corrected Diebold–Mariano test (A.4 step 6) between the best and second-best model, but do not let it decide the winner.

  5. Refit the winner on the full series before saving it or forecasting into the future. Write H, T, the scheme used (“all origins” or “k = 10”), the origin dates, and the per-origin and averaged metrics to results.json, so the user can see what the ranking was based on.

B.2 Plan for L1: statistics that do not depend on the input distributions¶

If each input goes through its own increasing transform (any marginal distribution), two things do not change. One is the order of the points along each input. The other, approximately, is the ratio of neighbouring gaps between sorted values, because a smooth transform stretches two adjacent gaps by about the same factor. So the design can be tested without knowing the marginals:

  • Spacing ratio (marginal stratification, separates LHS / Sobol from Random). For each input, sort the values, take the gaps s_i, drop the outer 5% at each end (that is where the transform’s slope changes fastest), and compute r_i = s_{i+1} / (s_i + s_{i+1}). For i.i.d. sampling r ~ Uniform(0, 1), so E|r - 0.5| = 0.25. Stratified designs space their points more evenly. Use the mean of |r - 0.5| over inputs.

  • Rank discrepancy (joint structure, separates Sobol from LHS / Random). Centered discrepancy of the rank-transformed design (rank - 0.5) / n. Ranks are unchanged by any increasing transform. LHS and i.i.d. designs have the same rank pattern (independent random permutations), but a Sobol / Halton design does not.

Steps:

  1. In detect.py, add spacing_ratio(U) and rank_log_cd(U) (the latter skipped above MAX_N_DISCREPANCY, like log_cd), and a marginals argument:

    • "uniform": today’s statistics, plus the two new ones. Most power when the inputs really are uniform on a box.

    • "any": only the transform-invariant statistics (spacing ratio, rank discrepancy). Valid for any continuous marginals.

    • "auto": run both and report "uniform" if it finds a consistent method, otherwise "any". Say in the explanation which one was used. (Decision B-1)

  2. Inputs with tied or rounded values make gaps of 0, which breaks the spacing ratio. Treat an input with more than 5% zero gaps as discrete, and add that rule to the existing levels <= n/2 rule.

  3. Meaning of “Random” in "any" mode: i.i.d. points whose inputs are independent, with any marginals. Observational data usually has correlated inputs, which raises the rank discrepancy, so it still comes out “Uncertain”. Data that really is i.i.d. from, say, a normal distribution will now be called “Random”, which is correct. Document this in the module docstring and in the LHS app’s guide.

  4. compare_sample_methods keeps its YAML transform: known marginals give the most power. When any input’s KS p < 0.05 (YAML does not fit), rerun with marginals="any" and say so.

Risks to check in validation: densities with a near-zero gap in the middle (bimodal), very small n (< 20), where the 5% trim leaves few gaps, and inputs rounded to 2–3 decimals.

  3. Never test imputed values. Rows with any missing input are left out of the detection, and the report says how many.

  4. Multi-fidelity (page 02): each fidelity level is its own design, so detect per level and show one line per level.

B.4 Open decisions¶

  • B-1. Default marginals mode. Recommendation: "auto" (prefer "uniform", fall back to "any"). It gives the most power when inputs are uniform and still works when they are not. The alternative, "any" everywhere, is simpler and never wrong about the marginals, but loses the centered discrepancy and NN statistics, which are what separate LHS from Sobol in higher d.

  • B-2. Whether rows with a missing response count as design points (B.3 step 1). Recommendation: yes. They were sampled; the response is what is missing.
