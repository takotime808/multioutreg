Multi-Fidelity Surrogate Models page¶

The Streamlit page multioutreg/gui/pages/02_Multi_Fidelity_Surrogate_Models.py fits multi-fidelity surrogates to a single CSV, picks the best configuration by grid search, and produces a downloadable HTML report (mf_model_report.html).

.venv/bin/streamlit run multioutreg/gui/Grid_Search_Surrogate_Models.py
# then choose "Multi Fidelity Surrogate Models" in the sidebar

An example dataset (x1, x2, fidelity_level, y1, y2, three levels) can be downloaded from the Other Dataset Examples page.

Input¶

One CSV with a fidelity level column plus input and output columns. Each unique value of the fidelity column is one level. In the form you choose:

Field

Meaning

Fidelity level column

Column whose values identify the levels (e.g. 0, 1, 2 or lo, hi).

Input / output columns

Features and targets. The fidelity column cannot be either.

Fidelity levels — ordered lowest → highest

At least 2. The last entry is the highest fidelity; everything is evaluated on it. Numeric levels start in ascending order, so 0 is the lowest.

Skip computationally expensive models

Leaves out the sklearn GP (O(n³)).

Fix random seed / Random seed

See Reproducibility. On by default (seed 0).

Compute conformal prediction intervals

Adds split-conformal intervals at the chosen alpha.

Level numbering. Number levels upward from 0 (lowest, cheapest) to the highest fidelity, as in Kennedy & O’Hagan (2000), SMT’s MFK and Emukit. Some benchmark sources, Mainini et al. (2022) and BenchmarkFcns, number the other way (f_1 or column 0 is the highest fidelity); reverse their levels before upload.

Missing values: target rows with missing values are always dropped; inputs can be dropped or KNN-imputed, with the imputer fitted on each level’s training split only.

What the page does¶

  1. Split. Each level is split 75/25 into train/test. Only the highest-fidelity test set is used for reported metrics. With conformal on, 20% of the highest-fidelity training split is held out for calibration and never used for fitting.

  2. Grid search. Every combination of multi-fidelity type and base surrogate is fitted:

    Type

    Candidate name

    How levels are used

    StackedVFMSurrogate

    StackedVFM+<base> (+augStd also feeds lower-level std)

    Each level’s model gets the lower levels’ predictions as extra inputs. Any number of levels. Where a level’s training inputs are also lower-level training inputs, those inputs get out-of-fold lower-level predictions (5 folds), so the model is not trained on over-accurate in-sample predictions.

    AdditiveCorrectionVFM

    AdditiveVFM+<base>, AdditiveVFM+<base>+rho1

    f_hi = ρ·f_lo + δ, with ρ fitted per output (Kennedy-O’Hagan AR1), or fixed at 1 (+rho1). A fitted ρ also scales the low-fidelity model’s error, so with a biased or smoothed low-fidelity model (e.g. RF) +rho1 can win. Only offered with exactly 2 levels.

    MultiFidelitySurrogate

    MultiFidelity+<base>

    One independent model per level. No coupling: the highest-level prediction ignores the lower levels.

    Base surrogates: RF, HGB, Linear, ElasticNet, Lasso, GP (unless skipped), plus LightGBM, XGBoost, CatBoost and SparseGP when their packages are installed.

  3. Selection. Candidates are ranked by cross-validated MSE over the highest-fidelity training rows; lower-fidelity data is used in full in every fold. The CV scheme depends on the number of highest-fidelity training rows (select_cv_strategy): repeated k-fold (×3, with k = max(2, min(5, n // 4))) for ≤ 100, shuffled 10-fold for ≤ 1000, shuffled 5-fold above that. Leave-one-out is only used when asked for (cv="loocv"). The test set is not used.

  4. Refit and evaluate. The winner is refit on all training data and scored once on the highest-fidelity test set.

  5. Comparison models. The winner’s base surrogate is also fitted on each level alone (used for the Fidelity Levels table; the highest level is the HF-only baseline). For an independent (MultiFidelity+…) winner the fitted per-level models are reused, so its baseline comparison is exact.

Reading the report¶

The report (Report format: Redesigned, the default) opens with a verdict and a scorecard, then answers one question per section. Reading the Report explains every section and the verdict rules; this table lists what is specific to a multi-fidelity run.

Section

Multi-fidelity content

How to read it

1 · Can I use it?

Scorecard column Low-fidelity data: test RMSE against the HF-only baseline. Findings and next steps name weak levels and outputs where an HF-only model is as good.

Helps ≤ −5%, No gain within ±5%, Hurts ≥ +5%.

2 · Accuracy per output

All metrics are on the highest-fidelity test set.

3 · Error bars

Gaussian and split-conformal coverage curves on the same axes. Conformal intervals are calibrated on held-out highest-fidelity training points (calibration residuals, not test residuals).

A curve below the shaded band = overconfident; coverage ≥ 1−α holds on average when calibration and test data are exchangeable.

4 · Low-fidelity data

A dumbbell of MF vs HF-only RMSE per output, an r vs R² chart of each lower level, and a table of runs per level.

High r with lower R² = informative but biased (multi-fidelity can correct this). |r| < 0.5 = the level carries little usable information.

5 · What drives outputs

SHAP shares and partial dependence of the highest-fidelity predictions, with input column names.

6 · Data adequacy

The input design of every fidelity level (normalized to [0, 1], one marker per level) and the sampling method inferred for each.

A statistical statement, not proof; see Appendix B of AUDIT_CHECKLIST.md for limits.

7 · Model selection

Every candidate’s CV RMSE with its fold spread; candidates whose spread overlaps the winner’s are marked Tied.

Among tied candidates, the simpler one is a reasonable choice.

Appendix

Thresholds, all metrics, the generated summary, per-level training sizes, selection and calibration scheme, seed and data hash.

Classic format¶

Report format: Classic keeps the previous layout:

Section

What it shows

How to read it

Summary

Auto-generated findings from the metrics below.

Start here.

Fidelity Levels

Per level and output: train/test n, output mean ± std, and r / R² of a model trained on that level alone, scored on the highest-fidelity test outputs.

High r with lower R² = informative but biased (multi-fidelity can correct this). Low r = the level carries little usable information.

Regression Metrics

R², RMSE, MAE and mean predicted std per output (highest-fidelity test set).

Multi-Fidelity vs HF-only Baseline

Same base surrogate trained only on highest-fidelity data.

Negative RMSE change = the lower levels helped.

Model Selection

Every candidate ranked by validation MSE; winner highlighted; failures with their error.

A small gap to the runner-up means the choice is not robust.

Uncertainty Metrics / Coverage Plot

Sharpness (mean std), empirical coverage of the 95% Gaussian interval, miscoverage, Gaussian NLL (omitted when any std is 0).

Coverage below nominal = overconfident std; above = conservative.

Conformal Prediction Intervals

Split-conformal intervals and Gaussian-vs-conformal coverage curves (calibration residuals, not test residuals).

Coverage ≥ 1−α holds on average when calibration and test data are exchangeable.

Predictions vs True

Ordered intervals and per-output scatter with ±std error bars.

SHAP / PDP

Explanations of the highest-fidelity predictions, with input column names.

Sampling & Input Space

Sampling method inferred from the full highest-fidelity input design (Monte Carlo test from multioutreg.sampling.detect), and a scatter (2 inputs) or UMAP (> 2 inputs) of that design.

A statistical statement, not proof; see Appendix B of AUDIT_CHECKLIST.md for limits.

Additional Diagnostics

Residuals (observed − predicted) vs predicted with a trend band; error histograms (predicted − observed).

A trend or offset from zero = systematic bias. Note the opposite sign conventions.

Appendix

Per-level training sizes, test size, selection/calibration scheme, seed.

Interpretation caveats¶

  • An independent winner means multi-fidelity did not help. MultiFidelity+<base> uses only highest-fidelity data for its highest-level prediction, so if it wins, no coupled model beat high-fidelity data alone on validation. The generated summary (in the appendix of the redesigned report) says so explicitly.

  • Small test sets are noisy. The Summary warns below 30 highest-fidelity test points. The MF-vs-baseline difference on such sets can be within run-to-run noise.

  • Uncertainty can be badly miscalibrated (e.g. SparseGP std collapsing to its floor on noiseless data). Prefer the conformal intervals when the coverage plot falls below the diagonal.

Reproducibility¶

With Fix random seed checked (the default), one seed drives:

  • the train/test, validation and calibration splits;

  • every base surrogate with randomness, via its own seed argument (random_state for RF, HGB, GP, ElasticNet/Lasso, LightGBM, XGBoost and SparseGP; random_seed for CatBoost; Linear is deterministic). Mapping: _SEED_KWARG / _seeded in the page module;

  • the bootstrap band of the residual plot.

Two runs with the same data, settings and seed on the same day produce a byte-identical report (the redesigned report records the date). Uncheck the box to see run-to-run variation (the report then records the seed as “not fixed”). Without a seed, SparseGPSurrogate in particular gives a different model on every fit.
