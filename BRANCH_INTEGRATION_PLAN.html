2.5 Multi-objective regret metrics + model download — from moo-regret¶

Attempt: new multioutreg.metrics subpackage with hypervolume, scalarized and ε-indicator regret plus an iterative RegretTracker; show them with user-set pass/fail thresholds in the Auto-Detect GUI page and the HTML report; let users download the trained model as .joblib.

Source: e62d31c — multioutreg/metrics/{__init__,multiobjective_regret}.py, multioutreg/metrics/README.md, tests/unit/metrics/test_multiobjective_regret.py, page 01 diff, report/template.html regret section.

  • Keep:

    • pareto_mask, mixed min/max via minimize=[...], default HV reference point worst + 10% span, exact 1-D/2-D HV, pymoo HV for higher dimensions, scalarized regret with flexible weight shapes and reduce options, additive ε-indicator, RegretTracker;

    • GUI: HV reference margin / custom reference, scalarization weights, max-acceptable thresholds with ✅/❌ status lines;

    • report: “Multi-Objective Regret” section (regret_metrics, regret_bounds, regret_settings);

    • “Download Trained Model (.joblib)” button next to the HTML report download (session-state persistence is already on main);

    • the README in multioutreg/metrics/ (rationale for each metric/default), moved into Sphinx docs.

  • Fix / change:

    • The regret definition is wrong for surrogate evaluation. The branch compares the front of predicted values to the front of true values (HV(front(Y_true)) − HV(front(Y_pred)), clipped at 0). An optimistic model can then score zero regret while choosing bad designs, and the clipping hides it. Standard decision regret evaluates the true objectives at the points the model selects:

      • HV: HV(front(Y_true)) − HV(Y_true[pareto_mask(Y_pred)]) (≥ 0 by construction);

      • scalarized: for each w, x* = argmin_x w·Y_pred(x), regret w·Y_true(x*) − min_x w·Y_true(x) (≥ 0);

      • ε: ε-indicator of Y_true[pareto_mask(Y_pred)] vs front(Y_true). Keep the current “front-fidelity” comparison as an optional separate metric if wanted, but name it differently.

    • Scalarized regret with raw weights is dominated by the largest-scale objective. Normalize objectives (e.g. by the true ideal/nadir range) before applying weights.

    • The m > 2 Monte Carlo HV fallback is a Python loop over 20 000 samples with a fixed seed and no error estimate. Vectorize it, expose n_samples, and warn when it is used; prefer exact HV via pymoo.

    • pymoo was added as a hard dependency. Make it an optional extra [moo] with the 2-D exact path and MC fallback when absent.

Before deleting branches¶

Deleting a branch makes its commits unreachable; GitHub and local git gc will eventually drop them, and the <sha>:<path> pointers above stop working. Archive the tips as tags first (cheap, keeps the source readable):

for b in crossval-datasize-dep ts-review moo-regret pca_sample_detection integrate-acf; do
  git tag "archive/$b" "origin/$b"
done
git tag archive/active-learning-prototype active-learning-prototype   # local-only branch
git push origin 'refs/tags/archive/*'

Then delete:

# remote (keep gh-pages)
git push origin --delete crossval-datasize-dep ts-review moo-regret \
  pca_sample_detection integrate-acf main-backup-pre-ai
# local
git branch -D audit-critical-fixes integrate-acf active-learning-prototype
